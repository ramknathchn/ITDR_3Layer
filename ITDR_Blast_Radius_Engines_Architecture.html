Blast Radius Engines: Technical Implementation & Traversal Specification

Deep-dive architectural documentation detailing the technical implementation, backend services, T-SQL graph algorithms, dataset schemas, and full traversal walkthroughs for the three distinct Blast Radius engines in the ITDR 3-Layer Platform.

1. Architectural Overview of the Three Engines

The ITDR 3-Layer Platform separates blast radius calculations into three purpose-built engines to address identity hygiene, single-entity infrastructure exposure, and threat-wide cumulative blast radius.

1. Standard Graph Blast Identity Focus

User identity-centric graph engine measuring direct and inherited privilege accumulation across Active Directory groups and Entra ID cloud roles.

  • Backend Service: backend/services/graph_service.py
  • Frontend View: <graph-screen>
  • Target Scope: Single User Identity (e.g. USER_AMILLER)
  • Traversal Method: In-Memory BFS & Neo4j Cypher
2. 3-Layer Rule Engine Blast Single Entry Focus

System-level graph engine executing a 5-hop recursive T-SQL CTE traversal across hybrid infrastructure starting from a single compromised entry entity.

  • Backend Service: backend/services/blast_radius_rule_engine.py
  • Frontend View: <rule-engine-blast-screen>
  • Target Scope: Single Asset Entity (e.g. EC2-APP-01)
  • Traversal Method: T-SQL 5-Hop Recursive CTE
3. Threat Bulletin All-Entry Blast Multi-Entry Focus

Multi-entry threat engine resolving all compromised entry vectors for a CTI bulletin and executing parallel 5-hop CTE traversals to compute cumulative risk.

  • Backend Service: backend/services/blast_radius_rule_engine.py
  • Frontend View: <threat-bulletin-blast-screen>
  • Target Scope: Threat Bulletin ID (e.g. TB-2026-4472)
  • Traversal Method: Parallel Multi-Entry CTE & Merged Graph

3. Technical Implementation & Full Traversal Details

3.1 Engine 1: Standard Graph Blast Radius Engine
Architecture & Service Implementation backend/services/graph_service.py
The Standard Graph Blast Radius engine focuses on identity-centric entitlement analysis. It queries identity profiles and event logs to trace how privileges accumulate from a user account to groups, administrative roles, and subscribed cloud applications.

API Endpoint Specification:

GET /api/graph/blast-radius?identity_user=USER_AMILLER&bulletin_id=TB-2026-LIVE

Response Payload:
{
  "user": "USER_AMILLER",
  "blast_radius_score": 84.5,
  "direct_entitlements": ["Domain Users", "Cloud Contributors"],
  "reachable_nodes": [
    { "id": "ROLE_AZURE_CONTRIBUTOR", "type": "AZURE_ROLE", "depth": 1 },
    { "id": "APP_FINANCE_PROD", "type": "ENTERPRISE_APP", "depth": 2 }
  ]
}

Full Traversal Step-by-Step Walkthrough:

USER_AMILLER (User Identity) GRP_FINANCE_ADMINS (AD Group) Azure Contributor Role APP_FINANCE_PROD
  • Step 1 (User Root): Starts at identity_user = 'USER_AMILLER' in identity_profiles.
  • Step 2 (Group Membership): Traverses MEMBER_OF edges to fetch Active Directory security groups (e.g. GRP_FINANCE_ADMINS).
  • Step 3 (Role Inheritance): Traverses ASSIGNED_ROLE edges to fetch assigned Azure RBAC / Entra ID Directory Roles.
  • Step 4 (Application Reach): Identifies all enterprise applications and subsystems accessible via inherited roles.
3.2 Engine 2: 3-Layer Rule Engine Blast Radius Engine
Architecture & Service Implementation backend/services/blast_radius_rule_engine.py
The 3-Layer Rule Engine Blast Radius computes transitive system-level exposure across 5 topological hops. It executes a 5-hop recursive T-SQL Common Table Expression (CTE) query directly against Microsoft SQL Server table security_blast_radius_edges.

Mathematical Risk Scoring Model:

$$\text{Blast Radius Score} = \sum_{i=1}^{N} \left( \text{Criticality}_i \times \text{Sensitivity}_i \times \frac{1}{\text{Hop Depth}_i} \right)$$

Header: Content-Type: application/json
Payload: { "entry_entity": "EC2-APP-01" }

Full 5-Hop Traversal Step-by-Step Walkthrough:

Hop 0: EC2-APP-01 Hop 1: iam-role-app-executor Hop 2: AWSAdministratorAccess Hop 3: Vault secret/data/database/prod Hop 4: PAM Bastion sys-bt-pam-bank-001 Hop 5: S3 bank-customer-pii-vault
  • Hop 0 (Compromised Entry Point): Attacker gains initial access to EC2-APP-01 via SSRF or IMDSv1 exploitation.
  • Hop 1 (Direct IAM Role Binding): EC2-APP-01 holds attached instance profile iam-role-app-executor.
  • Hop 2 (Cloud Role Assumption): Attacker uses stolen temporary STS credentials to call sts:AssumeRole for AWSAdministratorAccess.
  • Hop 3 (Vault Secret Retrieval): Administrator access allows fetching root credentials from HashiCorp Vault mount secret/data/database/prod.
  • Hop 4 (PAM Bastion Checkout): Stolen database credentials allow un-ticketed session checkout on BeyondTrust PAM bastion sys-bt-pam-bank-001.
  • Hop 5 (Target Exfiltration): Attacker accesses unencrypted S3 bucket bank-customer-pii-vault and exfiltrates 1.2M customer PII records.
3.3 Engine 3: Threat Bulletin All-Entry Blast Radius Engine
Architecture & Service Implementation backend/services/blast_radius_rule_engine.py
The Threat Bulletin All-Entry Blast Radius engine resolves ALL entry vectors belonging to a Threat Bulletin and executes parallel 5-hop CTE graph traversals for each entry point. It merges overlapping target assets and calculates the cumulative threat blast radius.

Cumulative Risk Scoring Formula:

$$\text{Cumulative Risk Score} = \sum_{k=1}^{M} \text{Individual Entry Score}_k$$
