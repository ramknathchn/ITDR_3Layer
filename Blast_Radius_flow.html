Attack Points Generation & Multi-Hop Blast Radius Traversal Architecture

Comprehensive architectural specification detailing the 5 attack point types generated by the ITDR application, the step-by-step layer traversal mechanics for discovering next hops, production source code for all three blast radius engines, and interactive visual flow diagrams.

1. Types of Attack Points (Entry Vectors) Generated

The ITDR 3-Layer Platform analyzes threat intelligence bulletins, telemetry events, and database topology to dynamically resolve 5 distinct classes of attack points (entry vectors). Each attack point type represents an initial compromise origin where an attacker gains a foothold:

1. User Identity

Human user accounts, executive accounts, kerberoastable SPNs, and domain admin credentials.

USER_JDOE svc_sql_production USER_AMILLER
2. Web & Compute

Public web instances, EC2 VMs, Kubernetes pods exposed via SSRF or IMDSv1 metadata endpoints.

EC2-APP-01 pod-payment-gw 10.240.10.15
3. Service Principal

Cloud App Registrations, OIDC Workload Identity Federations, and OAuth service principals.

APP-REG-001 sp-github-actions gcp-sa-deployer
4. Vault & Storage

HashiCorp Vault secret KV engines, public S3 buckets, and Azure KeyVault instances.

secret/data/prod s3-pii-vault kv-finance-keys
5. PAM & Socket

Privileged Access Management (PAM) bastions, open SSH/RDP management ports, and network sockets.

sys-bt-pam-bank-001 bastion-rdp-01 tcp:22-open

2. Layer Traversal Mechanics: How Next Hops Are Found

Finding the Blast Radius requires traversing directional edges in security_blast_radius_edges up to a maximum depth of 5 hops. Algorithmically, the next layer is found by matching the target node of the current layer as the source node of the subsequent layer:

Hop 0: Entry Point Initialization Initial Foothold
Attacker establishes compromise on entry vector $E_0$ (e.g. EC2-APP-01 or USER_JDOE). Depth = 0.
Hop 1: Direct Resource & Entitlement Binding (How Next Layer is Found) Direct Reach
Query locates all edges where source_node = E_0. Resolves attached instance profiles and AD group memberships.
Match Condition: source_node = 'EC2-APP-01' → Target Found: iam-role-app-executor.
Hop 2: Cloud Role Assumption & Token Exchange Role Assumption
Query locates edges where source_node matches any Hop 1 target. Traverses STS_ASSUME_ROLE and ASSIGNED_ROLE edges.
Match Condition: source_node = 'iam-role-app-executor' → Target Found: AssumeRole: AWSAdministratorAccess.
Hop 3: Secrets Vault & API Key Extraction Vault Mount
Query locates edges where source_node matches any Hop 2 target. Traverses VAULT_READ and API_KEY_THEFT edges.
Match Condition: source_node = 'AWSAdministratorAccess' → Target Found: secret/data/database/prod.
Hop 4: Transitive PAM Bastion & Privileged Session Checkout PAM Bastion
Query locates edges where source_node matches any Hop 3 target. Traverses PAM_SESSION_CHECKOUT and UNAUTH_SESSION edges.
Match Condition: source_node = 'secret/data/database/prod' → Target Found: sys-bt-pam-bank-001.
Hop 5: Critical Core Infrastructure & Sensitive Data Exfiltration Target Exfiltration
Query locates edges where source_node matches any Hop 4 target. Reaches root target storage buckets, Domain Controllers, or SWIFT databases.
Match Condition: source_node = 'sys-bt-pam-bank-001' → Target Found: bank-customer-pii-vault.

3. Implementation Code & Traversal Logic (3 Blast Types)

3.1 Type 1: Standard Identity Graph Blast Radius Engine

Uses Python in-memory Breadth-First Search (BFS) / NetworkX graph traversal to calculate identity privilege accumulation: 

# backend/services/graph_service.py - In-Memory BFS Traversal Logic
def calculate_identity_blast_radius(user_identity: str, graph_edges: list) -> dict:
    visited = set()
    queue = [(user_identity, 0, [user_identity])]
    reachable_nodes = []
    
    while queue:
        current_node, depth, path = queue.pop(0)
        if current_node in visited or depth > 4:
            continue
        visited.add(current_node)
        
        if depth > 0:
            reachable_nodes.append({
                "node": current_node,
                "depth": depth,
                "path": " -> ".join(path)
            })
            
        # Find next layer matching current_node as source
        next_layer = [e["target"] for e in graph_edges if e["source"] == current_node]
        for nxt in next_layer:
            queue.append((nxt, depth + 1, path + [nxt]))
            
    return {"identity": user_identity, "reachable_nodes": reachable_nodes}

3.2 Type 2: 3-Layer Single-Entity Rule Engine Blast Radius

Executes a 5-hop recursive T-SQL Common Table Expression (CTE) query directly against Microsoft SQL Server: 

-- backend/services/blast_radius_rule_engine.py - 5-Hop T-SQL CTE Traversal
WITH BlastRadiusCTE AS (
    -- Anchor Member: Hop 0 Entry Point Match
    SELECT 
        source_node, 
        target_node, 
        relationship, 
        1 AS hop_depth,
        CAST(source_node + ' -> ' + target_node AS VARCHAR(MAX)) AS path_trace
    FROM security_blast_radius_edges
    WHERE source_node = @entry_entity

    UNION ALL

    -- Recursive Member: Join next layer where source_node matches previous target_node
    SELECT 
        e.source_node, 
        e.target_node, 
        e.relationship, 
        cte.hop_depth + 1 AS hop_depth,
        CAST(cte.path_trace + ' -> ' + e.target_node AS VARCHAR(MAX)) AS path_trace
    FROM security_blast_radius_edges e
    INNER JOIN BlastRadiusCTE cte ON e.source_node = cte.target_node
    WHERE cte.hop_depth < 5
)
SELECT DISTINCT 
    target_node AS target_entity, 
    MIN(hop_depth) AS hop_depth, 
    relationship AS relationship_type
FROM BlastRadiusCTE
GROUP BY target_node, relationship;

3.3 Type 3: Threat Bulletin All-Entry Cumulative Blast Radius

Resolves all entry vectors belonging to a Threat Bulletin, executes parallel 5-hop CTEs, merges overlapping nodes, and calculates cumulative risk score: 

# backend/services/blast_radius_rule_engine.py - Multi-Entry Aggregation Logic
def calculate_bulletin_blast_radius(self, bulletin_id: str) -> dict:
    entry_points = self._resolve_all_bulletin_entry_points(bulletin_id)
    cumulative_score = 0.0
    combined_assets = {}

    for ep in entry_points:
        # Execute Single-Entity 5-Hop CTE for each entry vector
        res = self.calculate_blast_radius(ep["id"])
        cumulative_score += res.get("blast_radius_score", 0.0)

        # Merge overlapping target nodes & flag multi-entry overlaps
        for asset in res.get("reachable_assets", []):
            ent = asset["entity"]
            if ent not in combined_assets:
                combined_assets[ent] = {**asset, "entry_points": [ep["id"]]}
            else:
                if ep["id"] not in combined_assets[ent]["entry_points"]:
                    combined_assets[ent]["entry_points"].append(ep["id"])

    return {
        "bulletin_id": bulletin_id,
        "cumulative_score": round(cumulative_score, 2),
        "total_combined_assets": len(combined_assets),
        "reachable_assets": list(combined_assets.values())
    }

5. Construction of Table security_blast_radius_edges & Source Files Pipeline

The global graph table security_blast_radius_edges serves as the primary data store queried by the T-SQL 5-Hop Recursive CTE engine. This section specifies its database DDL schema, the backend data generator pipeline, and the source files used to construct the directional edges.

5.1 DDL Schema Definition (SQL Server)

-- backend/db/blast_radius_migrator.py - Table DDL
CREATE TABLE security_blast_radius_edges (
    edge_id VARCHAR(128) PRIMARY KEY,
    source_entity VARCHAR(128) NOT NULL,
    source_type VARCHAR(64) NOT NULL,
    target_entity VARCHAR(128) NOT NULL,
    target_type VARCHAR(64) NOT NULL,
    relationship_type VARCHAR(64) NOT NULL,
    hop_count INT DEFAULT 1,
    criticality_weight FLOAT DEFAULT 1.0,
    sensitivity_weight FLOAT DEFAULT 1.0,
    raw_edge_json NVARCHAR(MAX),
    created_at DATETIME DEFAULT GETDATE()
);
